Для мониторинга проекта будет использоваться дашборд со следующей структурой:
Блок 1: Общий статус проекта (Overall Status - RAG)
Статус проекта: GREEN (Проект идет по плану, риски под контролем).
Блок 2: Ключевые метрики (Key Metrics)
Использовано времени: 80% (Текущая дата / Длительность).
Выполнено задач: 70% (Завершенные Story Points / Всего).
Консистентность каталога: >= 99% успешных E2E-операций (цены/наличие/кастомизация).
Успешность создания заказа: >= 99% (корзина → заказ + сохранение состояния).
Успешность оплаты: >= 99% завершенных оплат в тестовом контуре (webhook Stripe → конечный статус заказа).
Скорость обновления статусов: p95 <= 0.5 сек (событие → отображение в SPA).
Доставка сообщений чата: p95 <= 2 сек (ChatClient → клиент).
Время отклика SPA по ключевым страницам: <= 2 сек до интерактивности.
Доступность ключевых API/хабов: >= 99.9% на период активного тестирования.
Блок 3: Статус вех (Milestones Status)
Требования собраны — Выполнено.
Catalog: API + UI карточки продуктов — Выполнено.
Order: корзина + создание заказа + статусы — Выполнено.
Payment: обработка webhook Stripe — В работе.
Geo/Venue: привязка точки выдачи/доставки — В работе.
ChatClient: чат-канал и обработка позиций заказа — В работе.
SPA: основные сценарии (Menu/Cart/Checkout/Order/History/Profile/Voice) — В работе.
Интеграционное тестирование и стабилизация — Не начато.
Блок 4: Топ-Риски и Проблемы (Top Risks/Issues)
Issue 1: Некорректные данные в каталоге (цены/наличие/кастомизация) приводят к ошибкам формирования заказа. (Ответственный: Catalog).
Risk 1 (Высокий): Недостаточная производительность backend/API и обновлений статусов при одновременных пользователях. (Ответственный: Backend/DevOps).
Risk 2: Ошибки конфигурации безопасности/интеграций (security/WAF, webhook Stripe, каналы чата) блокируют цепочку заказа. (Ответственный: Platform/Backend).
Risk 3: Срыв дедлайна из-за сложностей интеграции модулей и стабилизации оплаты/тестирования/деплоя. (Ответственный: PM + Tech Lead).
