# ChatClient: технологии и применение Microsoft Agent Framework (текст для диплома)

В рамках разработки сервиса `ChatClient` была выбрана архитектура, ориентированная на практическое применение методов искусственного интеллекта в задаче обработки пользовательских заказов на естественном языке. Технологической основой решения выступает платформа `.NET 9` и `ASP.NET Core Web API`, а центральным элементом AI-части является Microsoft Agent Framework, представленный в проекте пакетами `Microsoft.Agents.AI`, `Microsoft.Agents.AI.Workflows` и `Microsoft.Agents.AI.Hosting`. Выбор данного подхода обусловлен тем, что в прикладных системах недостаточно выполнить единичный запрос к языковой модели: требуется воспроизводимый, контролируемый и проверяемый процесс обработки данных, в котором каждый этап имеет четко заданную ответственность.

Microsoft Agent Framework рассматривает AI-логику как сочетание двух уровней. На первом уровне находится агент как интеллектуальный исполнитель, который использует большую языковую модель, системные инструкции и внешние инструменты. На втором уровне располагается workflow, то есть граф выполнения с явным описанием последовательности шагов и условий маршрутизации. Такое разделение особенно важно в производственных системах, потому что позволяет совместить гибкость LLM на уровне интерпретации текста с детерминированностью бизнес-процесса на уровне оркестрации. В результате система становится более прозрачной для тестирования, сопровождения и контроля качества.

В `ChatClient` этот подход реализован через двухэтапный AI-конвейер. На первом этапе агент `OrderTextNormalizerAgent` анализирует входную реплику пользователя, определяет, относится ли она к заказу, и выполняет нормализацию текста. Под нормализацией понимается исправление орфографических и грамматических ошибок, унификация формулировок и сохранение исходного смысла. На втором этапе агент `OrdeCreaterAgent` преобразует нормализованный текст в структурированное представление заказа. Если на первом этапе установлено, что сообщение не относится к заказу, выполнение переводится в отдельную ветку обработки нецелевого ввода. Таким образом, в системе реализована не только генерация ответа, но и логика условного перехода между сценариями, характерная для управляемых workflow.

С технической точки зрения ключевую роль играет `WorkflowBuilder` из `Microsoft.Agents.AI.Workflows`, который задает связи между executor-компонентами и содержит switch-маршрутизацию по результату промежуточного шага. Запуск конвейера выполняется через in-process модель исполнения (`InProcessExecution`), что позволяет интегрировать workflow непосредственно в HTTP-обработчик и возвращать результат пользователю в синхронном режиме API-вызова. Такой способ организации полезен для начального и среднего уровня нагрузки, когда приоритетом являются простота эксплуатации и минимальное количество промежуточной инфраструктуры.

Особое значение в проекте имеет механизм структурированного вывода. Оба агента работают с обязательным ограничением формата ответа через JSON-схемы, что снижает вариативность LLM-выхода и упрощает последующую машинную обработку. Иными словами, модель не возвращает произвольный текст, а формирует данные в заранее определенной структуре доменной модели заказа. Это критично для бизнес-приложений, где результат должен быть пригоден для автоматической передачи в следующие сервисы без ручной интерпретации.

Дополнительно в `ChatClient` реализован паттерн tool calling: агентам предоставляются доменные функции для доступа к каталогу продуктов и валидации модификаций ингредиентов. Взаимодействие с инструментами организовано через `AIFunctionFactory` из `Microsoft.Extensions.AI`, что позволяет преобразовывать C#-методы в инструменты, вызываемые моделью в процессе рассуждения. На практике это снижает риск галлюцинаций, поскольку агент не должен "придумывать" товары и параметры, а опирается на фактические данные внешних систем. Такой подход соответствует современной практике построения надежных AI-сервисов, где языковая модель отвечает за интерпретацию намерения, а фактическая точность обеспечивается инструментами и валидаторами.

Для семантического сопоставления пользовательских формулировок с каталогом применяется векторный поиск. Эмбеддинги текста формируются локально через `Ollama` с моделью `mxbai-embed-large`, после чего сравниваются с векторными представлениями карточек продуктов, сохраненными в `PostgreSQL` с расширением `pgvector`. В хранилище используется тип `vector(1024)`, а релевантность рассчитывается по cosine distance. Такая схема позволяет корректно обрабатывать разговорные, неточные или вариативные формулировки, что повышает устойчивость сервиса в реальных пользовательских сценариях.

Инференс чат-модели в текущей реализации выполняется через OpenAI-совместимый клиент (`Microsoft.Extensions.AI` + OpenAI SDK) с endpoint `GitHub Models`. Тем самым в проекте используется комбинированная архитектура: генеративная часть и reasoning выполняются через удаленный OpenAI-совместимый провайдер, а embedding-компонент размещается локально. Для интеграции с внешним каталогом применяется `Refit`, обеспечивающий типобезопасный доступ к REST API, а для повышения производительности и снижения количества повторных обращений используется кэширование.

По результатам анализа можно сделать вывод, что применение Microsoft Agent Framework в `ChatClient` является обоснованным с инженерной и исследовательской точек зрения. Фреймворк обеспечивает формальную оркестрацию AI-этапов, контролируемую маршрутизацию, совместимость с инструментальным вызовом функций и удобную интеграцию в .NET-среду. В совокупности с векторным поиском и структурированным выводом это формирует надежную основу для построения прикладного интеллектуального сервиса обработки заказов, пригодного для дальнейшего масштабирования и развития.
